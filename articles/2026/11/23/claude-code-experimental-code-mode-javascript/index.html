Claude Code въвежда експериментален Code Mode: Оркестриране на инструментални извиквания чрез JavaScript

Публикувано от Svetni.me Editorial на 23 ноември 2026 г. в Изкуствен интелект


Източник: InfoQ

Лабораторията за изкуствен интелект Anthropic добави експериментален режим, наречен Code Mode, към своя терминален агент за софтуерна разработка Claude Code, съобщава технологичното издание InfoQ [1]. Вместо моделът да заявява всяко отделно извикване на инструменти като Bash, Read или Edit в последователни стъпки (turn-by-turn), новата функционалност позволява на Claude да генерира изпълним JavaScript код, който програмно верифицира, паралелизира, филтрира и свързва множество системни операции в рамките на един скриптов блок [1, 2].

Функционалността е деактивирана по подразбиране, изисква версия Claude Code v2.1.323 или по-нова (като за екипи от агенти – Agent teams – се изисква минимум v2.1.326) и се активира изрично чрез променливата на средата CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 [1, 2]. От Anthropic предупреждават, че режимът е в експериментална фаза и неговото поведение или интерфейс могат да бъдат променени или премахнати във всяка следваща версия [1, 2].

От последователни заявки към програмна оркестрация в REPL среда

В стандартна интерактивна сесия с Claude Code агентът следва класическия цикъл на извикване на инструменти: заявява една операция, изчаква пълния суров резултат в контекстния си прозорец и едва след това генерира следващата стъпка [1]. При мащабни кодови бази този подход води до бързо раздуване на контекста със стотици редове междинни логове от търсене или тестови изходи, които моделът реално не се нуждае да пази в паметта си.

В Code Mode един генериран JavaScript скрипт може да стартира независими команди паралелно, да подава изхода от една операция директно като вход на следващата и да филтрира излишния шум, връщайки към езиковия модел единствено крайния релевантен резултат [1, 2]. Официалната документация на Anthropic илюстрира този процес със сценарий, при който един-единствен скрипт:

  1. Локализира целеви конфигурационен или сорс файл чрез rg (ripgrep);
  2. Променя параметър за лимит на повторните опити (retry limit) чрез Edit;
  3. Стартира автоматизирания тестов пакет чрез Bash;
  4. Филтрира изхода и връща към модела само пътя до файла и обобщения резултат от тестовете [1, 2].

Въпреки че оркестрацията се извършва вътре в скрипта, потребителският интерфейс в терминала продължава да визуализира всяко индивидуално извикване на инструмент и всяка кодова разлика (diff), докато самият генериран JavaScript код се записва и може да бъде инспектиран в прегледа на транскрипта (transcript viewer) [1, 2].

По отношение на времевите лимити за изпълнение:

  • Синхронно изчакване: Скриптове, чието завършване Claude изчаква активно, се прекратяват автоматично след 10 минути [1, 2].
  • Фоново изпълнение: Сесии, стартирани в режим auto или bypassPermissions, могат да прехвърлят изпълнението на скрипта във фонов режим за период до 2 часа, докато разработчикът продължава диалога с агента в основната нишка [1, 2].

Anthropic препоръчва използването на Code Mode при повтарящи се редакции в голям брой файлове, сложни търсения с нужда от програмно филтриране на резултатите и паралелно изпълнение на независими системни команди [1, 2].

Поддържани модели и архитектурни ограничения

Експерименталният Code Mode функционира единствено в интерактивни терминални сесии на нативната компилация (native build) на Claude Code през активен абонамент за Claude или акаунт в Anthropic Console [1, 2]. Режимът се поддържа върху следните модели от актуалната генерация на компанията:

  • Claude Opus 5.5
  • Claude Sonnet 5.5
  • Claude Haiku 5.5
  • Claude Fable 5.2 [1, 2]

Заедно с това Anthropic дефинира строги граници на средите, в които Code Mode не се поддържа:

  • Неинтерактивно изпълнение чрез флага -p (print/pipe режим);
  • Приложения, изградени върху Agent SDK;
  • Интеграцията в панела на VS Code и настолното приложение (Claude Desktop);
  • Достъп през облачни платформи на трети страни като Amazon Bedrock или корпоративни API шлюзове (gateways);
  • Организации с активирана политика за нулево задържане на данни (Zero-Data-Retention / ZDR) [1, 2].

Модел за сигурност: Статична класификация срещу динамични куки (Hooks)

Най-критичната архитектурна промяна в Code Mode засяга начина, по който системата за разрешения и защитните куки (PreToolUse hooks) инспектират действията на агента [1, 3, 4].

Всяко отделно извикване на инструмент вътре в генерирания JavaScript скрипт продължава да преминава през дефинираните правила за отказ (deny) и изискване на потвърждение (ask), както и през регистрираните PreToolUse куки [1, 3]. Съществената разлика се проявява в автоматичния режим на разрешения (auto mode):

  1. Инспекция преди изпълнение (Pre-execution review): В режим auto класификаторът за сигурност анализира целия JavaScript скрипт преди неговото стартиране, вместо да оценява всяко отделно извикване по време на изпълнение [1, 4]. Тъй като анализът е предварителен, класификаторът не може да види стойности, които се изчисляват динамично по време на работа на скрипта (runtime-computed values) [1].
  2. Съставни команди и инспекция на tool_input.code: В скриптов режим команда като git push може да достигне до защитна кука като част от верижна инструкция, например cd 'app' && git push [1]. Това изисква от архитектите по сигурност да проектират куките си така, че да парсват всеки компонент от командния низ, а куките, следящи REPL инструмента, трябва директно да инспектират суровия JavaScript код чрез полето tool_input.code [1, 3].
  3. Защита срещу атаки през клонирани хранилища: За да се предотврати автоматичното активиране на Code Mode от злонамерен конфигурационен файл при клониране на външно Git хранилище, режимът не може да бъде включван чрез проектни настройки (project settings) [1, 2]. Същевременно корпоративните администратори могат принудително да го забранят чрез централизираните управлявани политики (managed settings) [1, 2].

Емпирични резултати и позициониране спрямо MCP и Cloudflare

Макар Anthropic все още да не е публикувала официални бенчмаркове за спестени токени или латентност при Code Mode [1], ранните тестове от инженерната общност вече очертават конкретни параметри. Разработчикът Джордж (@bolyki) публикува сравнение между Code Mode и стандартния режим в осем интерактивни сесии с модела Sonnet 5.5 [1, 5]:

  • Консистентност: Идентични крайни резултати във всички тестови пускания [1, 5];
  • Размер на контекста: Между 20% и 25% по-малък контекстен прозорец [1, 5];
  • Ефективност при големи задачи: До 37% по-малко изразходвани токени и 19% по-ниска финансова цена при мащабни операции [1, 5];
  • Компромиси: Липса на реално ускорение във времето за изпълнение (wall-clock speed) и по-висок разход при съвсем малки, тривиални задачи заради първоначалния овърхед от генерирането на оркестриращия скрипт [1, 5].

Появата на Code Mode породи дискусии дали програмната оркестрация обезсмисля протокола Model Context Protocol (MCP). Рави Мадабхуши (Ravi Madabhushi), архитект на инфраструктура за агентна автентикация, опровергава подобни твърдения, подчертавайки, че Code Mode не променя слоевете за автентикация, оторизация и одитни политики [1, 6]. Агентът продължава да извършва същите базови извиквания със същите токени за достъп; реалната промяна се състои единствено в това колко междинен контекст достига до прозореца на модела и колко може да бъде отхвърлен локално преди това [1, 6].

Самата концепция и наименованието имат ясна технологична генеалогия:

  • Cloudflare Code Mode за MCP: Преди изданието на Anthropic, Cloudflare представи едноименен подход, който компилира MCP инструментите в TypeScript API, срещу което моделите пишат код вътре в изолирани (sandboxed) Cloudflare Workers, където системните привързвания (bindings) държат API ключовете напълно изолирани от генерирания код [1, 7].
  • Публикациите на Anthropic за програмно извикване: В предходен инженерен анализ за изпълнение на код с MCP Anthropic демонстрира работен поток, при който консумацията на токени спада драстично от 150 000 на 2 000 токена [1, 8]. Освен това Claude API вече предлага програмно извикване на инструменти (programmatic tool calling) в отдалечен контейнер за изпълнение на код [1, 9].
  • Локалното измерение на Claude Code: За разлика от облачните контейнери на API платформата или изолираните Workers на Cloudflare, новият Code Mode в Claude Code изпълнява оркестриращия JavaScript скрипт директно в локалната сесия на разработчика срещу вградените системни инструменти и локалната система за разрешения [1, 2].

Системен и архитектурен анализ: Преходът от декларативни JSON схеми към Тюринг-пълна локална оркестрация

Въвеждането на експерименталния Code Mode в Claude Code бележи фундаментален архитектурен завой в еволюцията на автономните софтуерни агенти: преминаването от императивен диалог с единични JSON извиквания към делегирана програмна екзекуция (Code-as-Action). Този преход носи три дългосрочни системни и макроикономически последствия за софтуерната индустрия:

1. Икономика на контекстния прозорец и амортизация на инференс разходите

Традиционният агентски цикъл (ReAct – Reason + Act) третира големия езиков модел като централен маршрутизатор на данни: ако агентът трябва да провери 40 файла и да сравни изхода от тестовете им, всички сурови данни преминават през вниманието (attention механизма) на трансформъра при всяка стъпка. Тъй като цената и латентността на инференса растат с натрупването на входни токени във всеки следващ ход, използването на фронтиър модел като Opus 5.5 или Sonnet 5.5 за елементарно филтриране на низове и управление на цикли е икономически неефективно. Изместването на контролния поток (forEach, Promise.all, регулярни изрази, условни разклонения) в лек локален JavaScript REPL превръща езиковия модел от изпълнител на цикли в компилатор на намерения. Емпиричното намаление от 37% в токените при големи задачи е пряк резултат от това, че локалният процесор на разработчика поема детерминистичната обработка на данните, оставяйки за невронната мрежа само семантичното вземане на решения.

2. Парадоксът на статичната верификация при динамично генериран код

Най-сериозното инженерно предизвикателство пред локалния Code Mode е фундаменталният конфликт между Тюринг-пълния скриптов език и статичните политики за сигурност. Когато един агент прави единично декларативно извикване (напр. Read(file="config.json")), системата за разрешения разполага с пълна видимост върху конкретните аргументи преди изпълнението. Когато обаче агентът генерира JavaScript програма, която конструира пътища до файлове и shell аргументи динамично чрез променливи и функции по време на изпълнение, предварителният класификатор в auto режим се сблъсква с класическия проблем за статичния анализ (сводим до проблема за спирането и теоремата на Райс).

Фактът, че в auto режим класификаторът оценява скрипта само веднъж преди стартирането му и не вижда изчислените по време на работа стойности, създава асиметрия в сигурността. Това обяснява защо Anthropic категорично забранява активирането на Code Mode през проектни конфигурации в хранилищата и налага PreToolUse куките да инспектират както всяка отделна runtime команда, така и пълния изходен код в tool_input.code. За корпоративните екипи по киберсигурност (SecOps) това означава, че защитните правила вече не могат да разчитат на елементарни регулярни изрази за начало на низ (като ^git push), а трябва да внедряват пълноценни AST (Abstract Syntax Tree) парсъри за bash и JavaScript в своите защитни куки.

3. Разделението между локални REPL агенти и изолирани облачни среди

Архитектурното разграничение между локалния Code Mode в Claude Code и изолираните облачни подходи (като Cloudflare Workers с изолирани bindings или контейнерното програмно извикване в Claude API) очертава двуслойното бъдеще на корпоративните агенти. Докато облачните контейнери гарантират строга криптографска и мрежова изолация на тайните (API ключове и токени), локалният терминален агент работи директно върху файловата система, SSH ключовете и локалния инструментариум на разработчика. Превръщането на локалния REPL в основен оркестратор на инструменти ще ускори търсенето на леки механизми за изолация на ниво операционна система (като macOS Seatbelt профили, Linux namespaces/Landlock и ефемерни микро-виртуални машини), които да позволяват на агентите да изпълняват паралелни JavaScript скриптове с максимална скорост, без да компрометират хост средата.
